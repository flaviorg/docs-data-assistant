# Defesas em camadas: leitura da matriz

A matriz é gerada por `npm run layers` a partir de `eval/attacks.v1.json` (19 ataques escritos para o projeto). Cada ataque passa por **cada camada sozinha**, sem LLM; `—` quer dizer que a camada não se aplica ao vetor. A tabela completa está no [README](../README.md#guardrails-e-matriz-de-ataques).

## O que a matriz mostra

- **As regras de entrada são a camada mais fraca.** Pegam a injeção direta óbvia, mas `ind-assistant` passa por elas e só é barrado pelo sanitizador de documentos. A defesa principal é arquitetural: modelo sem ferramentas de escrita, conexão somente leitura, authorizer, sanitização na ingestão e guarda de saída.
- **Redundância real contra escrita:** o `DELETE` e o `REPLACE INTO` são barrados pelo lexer, pelo authorizer e pelo `query_only`, cada um sozinho. O `REPLACE INTO` passava pelo lexer até a revisão final, porque `replace()` é função permitida; agora `INTO` é palavra-chave proibida.
- **Por que o lexer rejeita duas instruções:** em `sql-multi` (`... ; DROP ...`), o authorizer não vê o `DROP`, porque o `prepare()` do `node:sqlite` compila só a primeira instrução e descarta o resto em silêncio ([incidente](incidents/2026-10-04-prepare-descarta-instrucoes.md)).
- **Dado pessoal:** `customer_contacts`, `customers.name` e `load_extension` passam pelo lexer e pelo `query_only` (que só protege contra escrita) e são barrados pelo authorizer.
- **Produto cartesiano:** `sql-cross-join` é uma leitura permitida, barrada só pela regra `cross_join` do lexer. A variante com `ON 1=1` passa pelas três camadas estáticas; quem a corta é o prazo de execução: a SQL roda num processo filho que leva `SIGKILL` depois de `SQL_TIMEOUT_MS`, sem travar o servidor ([incidente](incidents/2026-10-04-produto-cartesiano-trava-o-servidor.md)). A matriz não tem coluna para o prazo; os testes `SQL-11` cobrem esse caso.
- **A guarda de saída vê o motivo da rota, os IDs citados e o bloco SQL:** `out-citation-id` é um ID inventado com o canário, que antes iria cru para o aviso `citation_dropped` ([incidente](incidents/2026-10-04-guarda-de-saida-sem-motivo-da-rota.md)). `out-sql-literal` é uma SQL com o canário num literal: a consulta, as linhas, as colunas e o último erro chegam à API e à página, e antes passavam ao largo da guarda ([incidente](incidents/2026-10-04-bloco-sql-fora-da-guarda-de-saida.md)).
- **A pergunta não forja trecho:** `dir-forged-document` fecha o `</documento>` e abre um `<documento id>` com o ID de um chunk real e um prazo inventado. A regra `system_tag` barra a tag na entrada e, se ela passar (com `GUARDRAIL_MODE=off`, por exemplo), o prompt `rag-answer` escapa `<documento` na pergunta como já fazia nos trechos ([incidente](incidents/2026-10-04-pergunta-forja-trecho-do-rag.md)).
